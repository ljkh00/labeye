PROBLEM STATEMENT
Every lab service keeps its own accounts. LabEye has local JWT users, and Proxmox, OPNsense, Wazuh and the 20 Lenovo stations each have separate logins. Onboarding a cohort means creating accounts by hand in several places, offboarding is inconsistent, and nobody can say for certain who has access to which device. Shared admin passwords cannot be traced to a person. DNS is already set up on OPNsense, but it is undocumented and has no directory behind it. The lab needs one authoritative identity source with role-based access that a small team can run each semester.
RESEARCH QUESTIONS
  1. How should an AD-based RBAC model (OU, group and tier design) be structured so that a single semester's cohort of students, lecturers and admins gets least-privilege access across heterogeneous lab services?
  2. How can AD DNS coexist with the existing OPNsense resolver without breaking name resolution on the other lab VLANs?
  3. To what extent does centralised identity cut the time spent on account administration each semester and improve auditability, compared with the current per-service accounts?
SCOPE & TASKS
  1. 01Deploy a Windows Server 2022 domain controller (one primary, plus a second DC as a stretch goal) as a VM on the Dell R440 from the FYP-1A golden image. Use the Azure Dev Tools for Teaching licence or the 180-day evaluation. Keep a local break-glass admin account on every integrated system so the lab still runs when the DC is down.
  2. 02Integrate DNS with the OPNsense setup that already exists: AD-integrated DNS is authoritative for the lab's internal AD zone, and OPNsense Unbound conditionally forwards that zone to the DCs and keeps resolving everything else. Document the as-built DNS, which is currently missing from the site.
  3. 03Design the RBAC model: an OU structure plus security groups (e.g. LAB-Students, LAB-Lecturers, LAB-Admins, and course groups such as CRS-NetSec), with a role-to-permission matrix covering every platform service. Use AGDLP-style nesting and a tiered admin model (Tier 0 DC/infra, Tier 1 servers, Tier 2 workstations).
  4. 04Connect LabEye (FYP-2A) to AD over LDAPS: AD group membership maps to the existing JWT roles (RequireRole), replacing local accounts. Students and lecturers log in with their lab domain accounts.
  5. 05Join the 20 Lenovo stations to the domain and apply baseline GPOs (password/lockout policy, logon banner, restricted local admin, LAPS for local admin passwords).
  6. 06Stretch: put Proxmox VE (AD realm with group sync), the OPNsense admin GUI (LDAP auth server) and the Wazuh dashboard (OpenSearch LDAP backend) behind AD groups, so staff use one identity to reach every lab device.
  7. 07Forward DC security events (4624/4625/4720/4728/4740, etc.) to the existing Wazuh manager through the Wazuh agent, and write a short set of identity-abuse detection rules (brute force, privileged-group changes, after-hours admin logons).
  8. 08Write semester operations SOPs: bulk student onboarding and offboarding from a CSV class list (PowerShell), password-reset flow, DC backup/restore with System State plus Proxmox snapshots, and an end-of-semester account purge.
OUT OF SCOPE / GUARDRAILS
  • No shared AD with attack labs. The production identity domain must never be reachable from Red/Blue lab segments. Vulnerable AD targets for 2B/2C (Kerberoasting, etc.) are separate throwaway forests from golden images.
  • No federation with the university's campus AD or Entra ID in this project. Campus IT approval is a future phase.
  • No Azure AD / Entra ID licences and no paid PAM tooling.
  • The pfSense migration is not in scope. LDAP auth is configured on the firewall that is live during the project.

HOW MY WORK ENABLES OTHERS
I give the lab one identity spine. LabEye (2A) stops managing its own users, lecturers get per-course access through group membership instead of shared passwords, and every admin action on Proxmox, OPNsense and Wazuh can be traced to a named account. DC security logs give 2C and 3B a new identity-layer detection source. Onboarding scripts turn the start-of-semester account setup into a single step, which is what makes the lab sustainable for whoever inherits it next.
